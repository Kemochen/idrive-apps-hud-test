# Adaptive Google Maps HUD for BMW ID7

## Status

Choose **Show on → HUD (experimental)** for windshield-only output. Turn on **HUD → Adaptive junction preview** to show the map when the next maneuver is within 2 km and the video is fresh. The switch defaults to off, using the regular HUD map and turn card. The choice is saved in the active profile. The previous diagnostics checkbox used the same preference, so an already selected checkbox becomes active on upgrade.

The baseline is the already tested Store experiment, `d6555d2`, descended from minakoto00's `79a4f20`. This keeps its existing app packaging, CarPlay compatibility gates, renderer integration, and logging. The separate branch leaves upstream and the previous release intact. Merging a newer renderer and patcher is a separate compatibility change.

On the owner's 2021 G05, resizing the turn card also resized the HUD lane arrows while navigating with Google Maps over CarPlay. Recommended lanes matched the center display and cleared after the maneuver. This is observational evidence for the existing `Guidance.currentLaneGuiding` render path on that car. It does not establish packet contents, road geometry or warning precedence.

## Interface inventory

| Interface or signal | Source-confirmed shape and what the branch uses |
| --- | --- |
| `de.bmw.infotainment.navigation.guiding.GuidanceEventList`, `Main_Instance` | `queryContent({viewConfigs:[...]})` returns `viewContent[].eventsInView[]`, a union keyed by maneuver or other event kind. The supported decoder reads `uid`, `formattedDistance`, maneuver enums and description text. Roundabout `exitNumber` is distinct from a motorway exit number. The latter and the exit destination may be present in description text. A typed enum such as `detailedGeometry` chooses an icon, not a geographically positioned road graph. Multiple events can be returned. This implementation uses the first maneuver and does not treat the following event's distance as valid. |
| `Guidance.currentLaneGuiding`, `Main_Instance` | `rows[0].lanes[]`, with `directionToFollow`, reported arrays of directions, `otherDirections`, and `isHighlighted`. An unreliable, incomplete, oversized or unmarked row does not pass the adaptive observer. A row shared across a UID change is withheld until it changes or clears. |

The on-unit typed proxy uses the SOME/IP catalog (`/etc/oap/someip/someip-interfaces.json`) for method, field, event, type and instance resolution. [waze-hud's schema adapter](https://github.com/JustAnotherPU/waze-hud/blob/6e9046f7f3de493f826896a0a6c17f1d335ca472/native/jap-waze-on-cluster/patch/pmg_schema.js) shows the firmware schema's method and event IDs, field getter/notifier IDs, event groups, unions, integer widths and string encodings. The collector extracts those IDs from the installed unit without issuing SOME/IP calls. The IDs and exact on-wire serialization for this G05 remain uncollected.

BMW's own [ID7 training manual §4.1.6](https://bmwtechinfo.bmwgroup.com/tech_training_manual/ST1855%20Displays%20and%20Controls%202018.pdf) documents High Guiding before maneuvers for instrument navigation. Its older [High Guiding technical description](https://www.press.bmwgroup.com/united-kingdom/article/attachment/T0128440EN_GB/192922) describes the short-range arrow-to-map transition and recommended lanes. That source's 150 m / 300 m examples predate ID7. It does not establish the 2021 G05 HUD's transition distances or all of its display priorities.

Apple documents maneuver, junction and lane metadata as separate application-provided capabilities in the [CarPlay Developer Guide](https://developer.apple.com/download/files/CarPlay-Developer-Guide.pdf). A raw Google Maps capture from this G05 is still pending. Current road, separate highway exit number/destination, route distinction, trustworthy speed/position, map scale, ID stability, and ordered maneuvers require on-unit checks. The HUD's existing map is the CarPlay second-screen video. It can serve as the junction preview if comparable frames prove it actually zooms and centers on the upcoming maneuver. Timing its visibility alone leaves the picture and camera unchanged.

## Architecture and configuration

1. Prefer the factory render path for phone turn guidance already displayed by BMW. There is no verified contract for submitting the handset's route and map matching into native High Guiding.
2. Adaptive mode displays the existing video whenever the next reported maneuver is at most 2 km away. This includes ordinary turns, lane changes, exits and roundabouts. Video visibility needs a valid distance and fresh guidance and frames. It remains continuous between consecutive maneuvers in range, even when the head unit omits a maneuver UID. The phone controls the map camera. The desktop simulator separately demonstrates synthetic localized junctions.
3. The desktop simulator demonstrates a custom low-clutter junction scene using real controller code and deliberately synthetic roads, route and vehicle position. A verified localized source must supply a fresh scene for the same maneuver ID. The controller rejects a generic secondary-display feed, incomplete lanes and stale data. The target is an arrow, distance and optional street at the upper left, with recommended lanes at the lower right.

`IDLE` and `FALLBACK` emit no custom display. `STANDARD_GUIDANCE` draws the current next maneuver only. `LANE_GUIDANCE` requires verified lane data. `JUNCTION_PREVIEW` additionally requires a complex maneuver, verified position, geometry tied to the active maneuver, and a fresh frame. A maneuver UID change clears obsolete lanes and map immediately and enters `MANEUVER_TRANSITION` with the new turn. The controller debounces entry to enhanced states; minimum dwell and distance hysteresis apply only while their data stays valid. Warning, unknown priority, stale frame, missing route, cancellation and disconnect override dwell. Speed increases the distance window through seconds-to-maneuver, within configured caps. Distance-only behavior is the fallback when speed is absent.

`tools/adaptive-hud.example.json` lists the desktop/controller settings. Brightness, opacity, size, position and zoom there affect the synthetic preview. The app's existing map width and position control the live video layer. Enable optional logging via `nav_diagnostics` in `waze-on-cluster.local.conf`. The native service expires the preview lease after 2.8 seconds without a new request and unmaps it when the app connection closes, the decoded video goes stale or the source freezes. It forces renderer yielding for adaptive previews. The collector reports restart count and CPU/memory counters when available. In-car resource use remains to be measured.

The upstream renderer's ID7 `hud_yield_slots` documents media/list and optional popup yielding. Coverage for Check Control, collision, pedestrian, speed-limit, ACC and Driver Assistance depends on the exact head unit and coding and remains to be measured on the car.

## Build and stationary validation

- Node 18+ for the host simulator and release scripts. Shipped app modules are also checked for Node 8.17 syntax. No browser network, package dependencies or API key are required for simulation.
- From the repository, run `node apps/robertn_waze_cluster/tools/test_adaptive_hud.js` and `node apps/robertn_waze_cluster/tools/build_adaptive_preview.js preview.html apps/robertn_waze_cluster/tools/adaptive-hud.example.json`. Open `preview.html` in a browser. Use the scenario selector, Previous, Next and Play.
- Run existing app tests under Linux to support their Unix sockets, and `make -C native/waze-on-cluster test`. The target build uses pinned Ubuntu 18.04 amd64/GCC 7.5 and verifies against head-unit ABI stubs. Run `bash apps/robertn_waze_cluster/tools/build_adaptive_usb.sh NEW_USB.zip` on a Linux host with Docker, Node and Git. The build takes committed HEAD from an isolated local clone and stamps lab-only version numbers there. The package includes the app and service only. It needs an existing `mgu-deploy >= 0.7.17` and `cluster-render >= 0.6.9` or an enabled source that offers them.
- Use the read-only inventory before an approved lab install. Review firmware identifier, CarPlay hash/build-ID, renderer version, OAP state, installed packages and the official source's exact rollback versions. Inspect original files and the inherited `.woc-orig` backup if present. Archives of prior firmware and credentials must stay private. Known build IDs and codings are defined by the inherited patcher, not by the model year. An unsupported or unknown build is grounds to stop the install and collect diagnostics.
- Select the lab app from Store's USB page only after explicit approval, parked. It shares unit IDs with stable and the earlier experiment. The Store may need removal of the old app and old `waze-on-cluster` tool, then a restart. Preserve shared tools. The inherited tool's installer can apply supported projection patches, using original binary backups and boot-recovery hooks. The adaptive feature itself adds no firmware write, and the package must stay a local lab build. Do not use it as an upgrade for a different active firmware or conflicting patch. Verify both lab version numbers and BMW speed/limits/warnings after the Store's restart, and confirm no custom HUD map is shown.
- For rollback, remove the lab app then its tool in Store, complete any required restart, and reinstall the exact previously recorded packages from their original source or prepared rollback USB. `tools/rollback_adaptive_mgu.sh` defaults to status. In approved maintenance, `--remove-adaptive` will remove only the two exact lab versions via upstream deploy cleanup. Use Store for the reinstall and its source bookkeeping. Do not transplant an original from another firmware or override a refused recovery. If restart/recovery fails, use the existing tool recovery procedure and collect its logs and backup hashes before more changes.
